# Автоматический стоп-лист

`/stop-list` читает опубликованный `GET /api/v1/stop-list` и `DishListResponse`
из `backend/docs/openapi.yaml`. В списке только активные недоступные блюда;
отключённое блюдо не является автоматическим стоп-листом. Запрос передаёт
только `search`, `page`, `page_size`, `sort=name`. Поиск буквальный, состояние
и пагинация сохраняются в URL и после восстановления сессии.

Карточка показывает серверные причины `ingredient_shortage`,
`only_expired_stock`, `recipe_missing`. Нативное раскрытие доступно с клавиатуры.
Рецепт и `shortages` принадлежат снимку ответа, количества остаются строками
и форматируются точно, включая тысячные. `required_quantity`,
`available_quantity`, `missing_quantity`, `expired_quantity` относятся к одной
порции этого блюда; `orders/check` не вызывается. `recipe` показывает полный
состав, `shortages` — только продукты с дефицитом; остаток остальных продуктов
этот контракт не содержит. Время снимка берётся из `meta.server_time`.

Ссылки на склад несут название и точный `product_id`; разрешения склада и
закупок берутся из общей матрицы ролей. При отсутствии рецепта только admin
получает ссылку на `/dishes/:id`; остальные видят объяснение и обращение к
администратору. Рецептура и закупки пока являются существующими точками входа
следующих историй, без заявления о готовом редактировании.

RTK Query подписывает чтение на `StopList` и `Dishes`. Поставка и создание
заказа уже инвалидируют `StopList`. Будущие изменения рецепта должны
инвалидировать `Dishes`/`StopList`. Вход на экран, возврат фокуса и восстановление
сети повторяют запрос; активное окно читает список каждые 30 секунд, чтобы
обнаруживать истечение без записи. Это периодическое обновление, а не SSE и
не локальный пересчёт запасов; внешнее изменение может отобразиться с задержкой
до следующего успешного чтения. При ошибке последнее успешное значение только
для текущих параметров помечено устаревшим; 403 полностью скрывает его.

MSW включается только явно в development/test. Сценарии показывают частичный
дефицит `0.001`, нулевой годный остаток с просрочкой и без неё, отсутствие
рецепта, 27 записей для пагинации, пустой список, изменение рецепта и истечение.
Синтетический молочный суп учитывает сохранённую F08-приёмку и F10-списание.
Production всегда обращается к реальному API. Эти проверки подтверждают
frontend, но не реальную S08/S15 интеграцию, БД, RBAC или серверный пересчёт.
