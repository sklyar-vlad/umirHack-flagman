# Оболочка и права доступа (F04)

`frontend/src/entities/session/model/navigation.ts` содержит единую матрицу из раздела «Роли» README. Её используют desktop sidebar, мобильное меню, вкладки рекомендаций, дополнительные разделы, guard маршрутов и выбор адреса после входа. Shared не зависит от сущностей, features или app.

| Раздел / путь | Доступ |
|---|---|
| Обзор `/`, склад `/inventory` | Все активные роли |
| Поставки `/supplies`, списания `/write-offs`, движения `/movements` | admin, manager, storekeeper |
| Заказы `/orders`, стоп-лист `/stop-list`, рецепты `/dishes` и `/dishes/:id` | admin, manager, order_operator |
| Рекомендации `/recommendations` | Все; переход на первую разрешённую вкладку |
| Продвигать блюда `/recommendations/offers` | admin, manager, order_operator |
| Закупить продукты `/recommendations/procurement` | admin, manager, storekeeper |
| Аналитика `/analytics`, прогноз `/forecast` | admin, manager |
| `/admin/products`, `/admin/categories`, `/admin/recipes`, `/admin/users`, `/admin/settings`, `/admin/audit` | admin |

`/admin` открывает первый доступный административный раздел (продукты). Все роли начинают с обзора. Внутренний returnTo очищается от query/hash и проверяется по наиболее конкретному разделу; запрещённый или неизвестный адрес заменяется стартовой страницей. Прямая ссылка на запрещённый раздел показывает «Недостаточно прав», сохраняя адрес. Неизвестный маршрут показывает 404 внутри оболочки. `/forbidden` доступен для явного экрана отказа.

SessionGate восстанавливает сессию и settings до монтирования оболочки. Ошибка восстановления предлагает повтор, ожидающая сессия показывает skeleton. RoleGate расположен выше бизнес-страницы: запрещённая страница не монтируется и не запускает свои query hooks. Скрытые кнопки не заменяют серверную проверку прав.

`frontend/src/features/access/ui/ApiAccessBoundary.tsx` показывает безопасный экран для нормализованного серверного `ApiError` со статусом 403. Он не раскрывает message/details, не переводит пользователя на login, не сбрасывает сессию или RTK Query и оставляет адрес. Другие ошибки обрабатывает вызывающая страница. Будущие страницы должны оборачивать результат запроса этим компонентом; состояние формы и последний успешный ответ держать выше boundary, чтобы они пережили отказ и повторную загрузку.

Оболочка использует существующие Inter, SVG, CSS-токены и UI-kit Drawer. Меню скрывается на desktop и открывается модальным диалогом на ширинах меньше 768 px; desktop и mobile используют один компонент Navigation. При переходе main получает фокус, skip-link ведёт к содержимому; Escape закрывает меню и возвращает фокус кнопке. Контролы имеют высоту не меньше 44 px.

Изменённые формы подключают существующий UnsavedChangesGuard. Переходы по меню, router Back/Forward и кнопка выхода проходят через blocker. Выход сначала переходит на `/logout`; только после разрешённого перехода SessionLogout вызывает контроллер F03 и очищает данные. StrictMode не дублирует запрос. Перезагрузка/закрытие изменённой формы используют native beforeunload. Принудительное истечение сессии сохраняет только allowlist владельца из F03, не ожидая пользовательского подтверждения.

## Границы истории и проверка

F04 создаёт входные страницы разделов с явным сообщением о будущем содержимом. Реальные списки, формы, счётчики и бизнес-запросы относятся к следующим историям; эти страницы не показывают придуманные складские данные.

Для разработки с `VITE_ENABLE_MOCKS=true` существующая панель сценариев предлагает role-admin, role-storekeeper, role-order-operator; стандартная fixture имеет роль manager. Выбранная роль применяется при следующем login/me. Mock-only cookie `flagman_mock_role` хранит роль тестовой сессии для reload и очищается при logout. Это не механизм production-авторизации.

Защищённый `/dev/access` проверяет локальный 403, pending/error и уход из тестового черновика на опубликованном healthcheck, включая MSW-сценарии forbidden/slow/server-error. Он доступен только в DEV, не отправляет предметные запросы и отсутствует в production. Публичные `/dev/ui` и `/dev/api` сохранены.

Проверки: `./scripts/frontend-checks.sh`; браузер — `cd frontend && npm run test:browser`. Для установленного Chromium задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Покрываются четыре роли, forbidden/404, восстановление, прямые ссылки, reload, Back/Forward, keyboard и ширины 360/390/1024/1440; тесты F02–F03 продолжают выполняться.

Auth login/me/logout используют изолированный адаптер F03. Текущий OpenAPI уже публикует эти операции; сопоставление адаптера с текущей версией и реальная проверка сессий/RBAC остаются отдельной интеграцией. MSW проверяет frontend-поведение, а не реальный сервер.

F05 заменяет входную страницу `/inventory` настоящим списком и панелями партий. `/supplies/:id` защищён той же матрицей, что список поставок; содержимое деталей и формы списания остаётся в последующих историях. Ссылки из партии передают supply ID и точные product_id/batch_id; номер строки показан в панели и подписи ссылки поставки. Возврат через Back восстанавливает фильтры склада. После входа сохраняются только опубликованные query-поля склада; неизвестные/секретные поля и hash удаляются.
