# Журнал действий (F24)

Администратор открывает `/admin/audit-log`; прежний адрес `/admin/audit` также работает.
Список использует существующий `GET /api/v1/audit-log`, без операций изменения журнала.
Навигация и RoleGate используют общую матрицу ролей; другим ролям запрос не отправляется.
Серверный 403 скрывает также последний список и открытые детали, не завершает сессию.
401 обрабатывает общий транспорт и восстановление входа; допустимые фильтры сохраняются.

## Чтение и фильтры

Поиск, actor_id (UUID или `system`), action, entity_type, entity_id, from/to, page,
page_size хранятся в URL. Сортировка только `-created_at`; верхняя граница периода
не включается. Даты вводятся в часовом поясе ресторана, отправляются RFC3339.
Изменение зоны требует явного пересмотра незавершённого периода, как на экране заказов.
Некорректные идентификаторы/периоды в URL блокируют запрос. Пагинация использует
серверный total; смена фильтра возвращает на первую страницу. Нажатие на имя автора
выбирает его действия. Дополнительные фильтры можно раскрыть отдельно от поиска.

Ответ проверяется Zod до помещения в RTK Query cache: ID, даты, опубликованные
действия/типы, метаданные страницы, уникальность записей, размер и total.
Используются `currentData`, обновление на focus/online и polling 10 секунд только
в активной вкладке. При ошибке остаётся список для тех же фильтров с предупреждением;
доступны повтор, пустой журнал, отсутствие результатов и возврат с пустой страницы.

## Запись и изменения

На desktop/tablet используется общий DataTable; на mobile — его карточки.
Отображаются ресторанное время, автор (null — «Система»), действие и объект.
Диалог показывает ID записи, ID объекта, request_id и сравнение разрешённых полей
before/after, в том числе вложенных рецептур и партий. Текст выводится средствами React,
без HTML-интерпретации. Типизированная allowlist повторяет backend AuditSnapshot:
посторонние поля и вложенные секреты отбрасываются до кеширования. Пароль/хеш
не показываются; password_change означает только факт смены пароля.

Ссылки ведут только на существующие страницы продукта, блюда, пользователя,
поставки, заказа или настроек. Недоступность текущего объекта не удаляет историю:
его экран показывает штатный 404/403. Для движений/категорий без отдельной страницы
отображается объяснение вместо выдуманного маршрута.

  фильтры/пагинация/reload, диалог и возврат фокуса, ошибки, недоступный объект,

- Проверена реальная интеграция с выключенным MSW на выделенной локальной PostgreSQL
  18 test-БД: cookie login, admin GET/filter/details/reload, `[from,to)`, total/page,
  422, Cache-Control no-store, исключение лишних snapshot-полей, 403 для manager.
  Также выполнены существующие PostgreSQL-тесты backend auditlog. QA-секреты,
  инструменты и отчёты находятся вне Git; это не доступ к production.

Макеты Figma: Desktop `10:2935`, Mobile `10:3171`. Переиспользуются существующие
AppShell, AdminNavigation, UI-kit и CSS-токены. Дополнительные фильтры и детали
реализуют требования F24; общий shell в рамках задачи не перестраивается.
MSW-сценарии audit-empty/slow/error/forbidden/invalid доступны только в явном
development/test режиме и не подменяют ошибки настоящего backend.
