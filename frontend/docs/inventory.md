# Склад и партии (F05)

## Контракты и слой данных

`frontend/src/entities/inventory/model/contracts.ts` проверяет схемы из `backend/docs/openapi.yaml`: InventoryListResponse, InventoryItem, BatchListResponse, Batch, CategoryListResponse. Количества — точные decimal-строки; агрегаты допускают значения выше numeric(14,3), преобразование для отображения выполняют общие функции без float. Единицы не смешиваются; несовместимые display_unit/дробные штуки и партии другого product_id отклоняются как INVALID_RESPONSE. Никаких backend-файлов F05 не меняет.

RTK Query endpoints инжектируются в общий API. Категории запрашиваются страницами по 100 до total: список не обрезается незаметно. Ошибка/повторённая страница не превращается в частичный успешный каталог. Каждая панель имеет собственные параметры/cache по product_id/status/sort/page и использует currentData; партии не запрашиваются до раскрытия. Закрытие удаляет подписку, cache сохраняется штатно. Разные ID партий одной поставки остаются разными строками.

## URL и навигация

Поддерживаются `search`, `category_id`, `filter=all|expiring|expired|out_of_stock|deficit`, `sort=name|nearest_expires_at`, `page` и `page_size` (1–100, по умолчанию 50). Поиск применяется кнопкой «Найти» или Enter. Смена поиска, категории, фильтра, сортировки/размера сбрасывает page; переход страницы сохраняет остальные параметры. URL является источником значений при reload/Back/Forward и возврате из другого раздела. Неверные параметры нормализуются перед отправкой, посторонние/повторные значения не передаются API.

Для возврата после login/истечения F05 явно разрешает только эти поля `/inventory`; неизвестные/секретные поля и hash отбрасываются. F06 добавляет отдельный allowlist списка поставок и его обратной ссылки (см. `supplies.md`); остальные разделы сохраняют только pathname. Весь роут склада находится за SessionGate и RoleGate.

## Семантика и состояния

Годный и физический остатки отображаются отдельно; просрочка не исчезает автоматически. Число партий, пересекающиеся counts, признаки и основной status берутся с сервера. Ближайший срок относится только к годным ненулевым партиям; null показан как «Нет годных партий», null target — «Не задан». Время отображается в timezone ресторана. remaining_seconds — серверное значение одного снимка, без пересчёта по часам браузера; ноль при expired остаётся просрочкой.

Раскрытие доступно нативной кнопкой с aria-expanded/aria-controls, Enter/Space. Панель по умолчанию сортируется FEFO (`expires_at`) и показывает ненулевые партии; «Вся история» передаёт status=all, «Израсходованные» — depleted. Сортировка -created_at предусмотрена контрактом. Пагинация и состояния загрузки/ошибки/пустоты независимы от списка; ошибка панели не скрывает продукт. При фоновом обновлении последняя выборка и раскрытая панель сохраняются; при смене параметров старая выборка не подставляется. Серверный 403 скрывает данные локально, сохраняя сессию. При несуществующей странице доступна кнопка возврата к первой.

Матрица F04 разрешает чтение всем четырём ролям, ссылки поставки и списания — admin/manager/storekeeper. depleted не имеет действия списания. Ссылка `/supplies/:id` ведёт на защищённый маршрут деталей, пока с входным экраном будущей истории; `/write-offs?product_id=…&batch_id=…` сохраняет точную партию для будущей формы. F05 не реализует и не заявляет завершёнными саму приёмку, детали поставки или мутацию списания.

## Проверки и границы интеграции

Vitest проверяет URL/page reset, опубликованные схемы, точные агрегаты/единицы, lazy-запрос, server counts/remaining_seconds, несколько строк одной поставки, expired-only, роли, локальную ошибку/пустоту и recovery, категории за первой страницей и отклонение чужих партий. Chromium проверяет 360/390/1024/1440, клавиатуру, overflow, прямую ссылку через login, reload, Back/Forward, пагинацию партий/историю, серверный 403 и независимые состояния.

Запуск: `./scripts/frontend-checks.sh`; `cd frontend && npm run test:browser`. Для системного Chromium: `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/Applications/Chromium.app/Contents/MacOS/Chromium`. MSW включается явно `VITE_ENABLE_MOCKS=true`, fixture-секреты только локальные; production никогда не использует моки. Эти проверки подтверждают frontend, не настоящий сервер.

Warehouse/categories/batches/auth уже опубликованы в текущем OpenAPI. Реальные cookie/CSRF/RBAC и данные S07 ещё не проверены frontend-сценариями: необходим отдельный прогон с отключёнными моками и тестовой серверной сессией. F03 адаптер остаётся изолированным; его сопоставление с опубликованным auth-контрактом не входит в F05.


## Выбор из поставки (F07)

Ссылка «На склад» из деталей поставки добавляет UI-only `product_id`/`supply_id` вместе с поиском по названию. Они не входят в API-параметры inventory. Отдельная панель получает точный ProductBrief из SupplyDetail и открывает существующий BatchPanel в `status=all`, включая depleted. Партии выбранной поставки отмечаются; остальные партии продукта доступны для сравнения. Панель независима от результата поиска склада и доступна admin/manager/storekeeper. Оператор не выполняет supply-запросы при подделанном выборе. Фильтры сохраняют выбор, сброс/«Снять выбор поставки» очищают его; login return сохраняет только валидные UUID.
