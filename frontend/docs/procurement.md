# Рекомендации закупок

F13: `/recommendations/procurement`; `/recommendations?tab=procurement` перенаправляет на тот же защищённый экран, сохраняя разрешённые фильтры. Доступ admin/manager/storekeeper. Оператор не получает вкладку и не монтирует запрос. Ссылки на стоп-лист доступны только admin/manager; кладовщик видит названия блокируемых блюд без недоступных переходов.

`GET /api/v1/procurement-recommendations` использует опубликованный `ProcurementListResponse`: поиск имени продукта, `category_id`, `page`, `page_size`. `sort` не отправляется. Серверный порядок сохраняется: число связанных блюд, нулевой годный остаток, имя/ID. Все количества остаются строками; отображение в display_unit точно сохраняет тысячные базовой единицы. UI не вычисляет закупку или прогноз спроса.

В ответ входят только положительные рекомендации для заданной положительной цели. `target_stock=null` означает отсутствие цели у продукта, а не ноль; такая запись не входит в контракт элемента закупок. Причины, годный/просроченный остаток, цель и связанные блюда берутся из снимка сервера. Отсутствие закупок не гарантирует доступность всех блюд. Продукт с целью может быть отключён: контракт не фильтрует активность.

Фильтры и страницы живут в URL, редактирование сбрасывает страницу; currentData не переносит строки предыдущих фильтров. Ошибка сети сохраняет текущий успешный снимок с предупреждением. 403 скрывает его. Загрузка категорий имеет отдельное восстановление, неизвестная категория из ссылки сохраняется. Доступны пустой список, отсутствие совпадений и выход за диапазон страниц.

Ссылка на склад несёт точный product_id и имя. Ссылка на приёмку несёт только product_id: форма выбирает его после загрузки активного каталога, только при отсутствии сохранённого черновика и ручных изменений. Количество, номер и даты остаются пустыми; переход никогда не выполняет POST. Неактивный продукт не выбирается. Сохранённый черновик имеет приоритет.

Procurement/Dishes tags обновляют активные подписки после приёмки/заказа; будущие изменения продуктов, целей и рецептов должны инвалидировать Procurement. Mount/focus/reconnect и опрос каждые 30 секунд в активном окне обновляют внешние изменения/истечение. Опрос не является SSE и может задерживать обновление.

MSW включается только явно в development/test. Сценарии закупок расширяют существующие синтетические поставки и заказы, используют отдельные демонстрационные цели для пагинации и не обращаются к серверу. Production сохраняет реальные запросы. Тесты MSW не подтверждают настоящую S12/S15 интеграцию, сессию, RBAC или данные БД; проверка с отключёнными моками остаётся отдельно.
