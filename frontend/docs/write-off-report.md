# Потери от списаний (F27)

`/analytics/write-offs` и входной `/analytics` открывают read-only отчёт для admin/manager. RoleGate не монтирует его для storekeeper/order_operator; серверный 403 скрывает последний успешный список. При остальных ошибках доступны повтор и явно отмеченный устаревший отчёт для того же фильтра.

GET `/analytics/write-offs` принимает только `from`, `to`, `product_id`, `reason=all|expiration|manual_writeoff`, `page`, `page_size`. API не поддерживает search или sort; строки сохраняют серверный порядок по имени, ID и единице. Фильтры хранятся в URL, меняющийся фильтр сбрасывает страницу. После входа allowlist сохраняет только опубликованные параметры. Неверные UUID, причина или период блокируют запрос.

Период вводится в зоне ресторана: нижняя граница включается, верхняя исключается. Неизменённые даты сохраняют точность исходного API, включая дробные секунды. При смене зоны ресторанных настроек незавершённый период требует явного пересмотра. Пустой отчёт, отсутствие совпадений, пустая дальняя страница, загрузка, ошибка и отказ доступа имеют отдельные состояния. Поллинг каждые 10 секунд работает только в активном окне.

Строка отображает историческое название, единицу, просрочку, ручные списания, сумму и число движений. Ключ строки — product_id + unit: исторически разные единицы одного продукта не объединяются. Decimal-строки валидируются и сравниваются через BigInt; агрегаты могут превышать numeric(14,3) отдельного движения. Схема проверяет сумму двух составляющих и целые штуки, envelope списка и уникальность групп. Количества форматируются общим quantity helper. Общей суммы между продуктами, смешивания единиц и денежной оценки нет.

Ручные движения и движения просрочки открываются отдельно в F26 с тем же продуктом и точным периодом; receipt/order_consumption не выдаются за потери. История не имеет фильтра unit: пояснение предлагает сверять единицу строки, если исторические единицы продукта различаются. Текущие названия и остатки со склада не подменяют исторические данные.

MSW использует общий stock-ledger-fixtures для F26 и отчёта, включая большие суммы, несколько продуктов и разные исторические единицы. Панель предлагает сценарии «Потери · …», в том числе дополнительный расход заказа, не увеличивающий отчёт. Все данные синтетические.

Проверки: `bash scripts/frontend-checks.sh`; `cd frontend && npm run test:browser -- write-off-report.pw.ts stock-movements.pw.ts navigation.pw.ts`. Покрываются 360/390/1024/1440, четыре роли, фильтры/страницы, история, Back/reload, точность количества и состояния. Настоящие API, роли и границы периода дополнительно проверяются с отключённым MSW на отдельной локальной PostgreSQL-базе; DSN и тестовые пароли остаются вне репозитория. Backend-тесты TestWriteOffAnalytics и TestAnalyticsRealOrderRefusalReplayCheckAndBothWriteOffs проверяют исторические группы, большие суммы, несовместимые единицы и исключение обычного заказа.
