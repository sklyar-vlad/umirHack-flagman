# Настройки ресторана

F23: `/admin/settings` доступен только admin. `GET /settings` и `PATCH /settings` следуют опубликованным `Settings` / `UpdateSettingsRequest` в `backend/docs/openapi.yaml`. Общая схема находится в `src/shared/api/settings-contracts.ts`; shared не импортирует entities/features/widgets/pages. Административные ссылки сохраняются при замене заглушек на экраны и используют существующую матрицу ролей.

Название обрезается по краям и содержит 1–200 Unicode-символов. Порог — целое число 1–720 часов. Timezone проверяется как поддерживаемое имя IANA; `Local` запрещён, сервер остаётся окончательным валидатором своего набора зон. Часовой пояс устройства не участвует в отображении ресторанных дат. Исторические UTC-моменты не изменяются.

Редактор начинает со свежего GET без подмены ревизии при focus/reconnect/инвалидации других списков. PATCH содержит `expected_revision` и только изменённые поля; пропущенные поля сохраняются. Повторные submit блокируются. После `REVISION_CONFLICT` значения формы остаются на месте. Нужно явно прочитать текущие настройки, сравнить их и подтвердить ревизию перед повторным сохранением. Неудачное чтение не снимает блокировку. `422` связывается только с разрешёнными полями и переводит фокус после завершения отправки. `403` блокирует запись; `401` проходит через общий механизм истечения сессии. Неизвестный исход записи не повторяется автоматически: требуется чтение и пересмотр. Выход с несохранёнными изменениями защищён общим диалогом.

После подтверждённого PATCH общие безопасные session.settings обновляют имя и timezone в оболочке и бизнес-экранах. Инвалидация Inventory/Batches/Dishes/StopList/HotOffers/Procurement/Dashboard обновляет активные серверные снимки; расчёты остатков, сроков и рекомендаций остаются на сервере. Явное чтение настроек также обновляет эти снимки, включая проверку после потерянного ответа. Старые ревизии не заменяют более новые общие настройки.

## Готовность автосписания

Контракт Settings не публикует capability готовности worker. Поэтому включение по умолчанию недоступно. `VITE_AUTO_WRITEOFF_READY=true` — явная настройка сборки окружения после подтверждения готовности фонового списания; она не выводится из успешного GET или наличия маршрута. Уже включённую функцию можно отключить при отсутствии этого признака. Включение требует подтверждения последствий: положительный просроченный остаток списывается в течение минуты, отключение не возвращает проведённые списания.

`FEATURE_UNAVAILABLE` обрабатывается независимо от HTTP-статуса: введённые значения сохраняются; включение блокируется, переключатель можно выключить и сохранить остальные поля. Флаг не заменяет серверную проверку. Playwright устанавливает его только в явно включённом MSW для проверки frontend-потока. Unit-тесты отдельно проверяют окружение без готового worker. Моки не запускают реальный worker и не подтверждают автоматическое списание.

## Черновики дат

Новый owner-scoped черновик приёмки хранит исходную timezone вместе с локальными датами. После смены settings.timezone ввод остаётся в исходной зоне; новая отправка блокируется до явного пересмотра. Пересмотр переводит все даты через исходные UTC-моменты, сохраняя секунды и дробную точность. Ошибка или DST-неоднозначность в исходной либо целевой зоне сохраняет весь прежний черновик, без частичного перевода. Пользователь проверяет даты перед отправкой. Старый черновик без timezone требует явного подтверждения всех дат; дальнейшее редактирование само по себе не назначает ему зону.

У неопределённой попытки приёмки уже есть неизменяемое тело с RFC3339-моментами и ключом. Смена timezone не меняет тело/ключ и не препятствует точному разрешённому повтору. Общие настройки не переписывают сохранённые UTC-моменты, корзины или payload существующих попыток.

Смонтированные фильтры истории поставок/заказов сохраняют зону ввода при обновлении общих настроек. Поиск приостанавливается до явного пересмотра; даты переводятся с сохранением исходных моментов, а применённые URL-границы остаются RFC3339. При новом открытии формы применённый UTC-период отображается в актуальной зоне. Ресторанные даты не переинтерпретируются по timezone браузера.

## Проверка интеграции

Разработка и тесты используют только opt-in development/test MSW. Синтетические настройки разделяются с auth/me, dashboard, складскими статусами и горячими предложениями; mock-storage содержит только настройки, без секретов. Production всегда использует реальные запросы. Реальная интеграция S19/S21, аудит/outbox, конкурентные серверные записи и работа worker отдельно не проверены.
