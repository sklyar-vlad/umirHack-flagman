# Недостача ингредиентов (F28)

`/analytics/ingredient-shortages` доступен admin/manager через существующую
матрицу ролей. Навигация аналитики сохраняет готовый отчёт потерь F27.
GET `/api/v1/analytics/ingredient-shortages` получает только `page`, `page_size`,
`from`, `to`. Период created_at — `[from,to)` в зоне ресторана; неизменённые
границы URL сохраняют исходные доли секунды. Смена зоны требует явного пересмотра
черновика периода с сохранением UTC-моментов.

Строка — исторические product_id/unit, последнее имя в выбранном периоде,
rejected_attempts_count и точная строка total_missing_quantity без предела одной
партии. Количества разных единиц не суммируются. Порядок сервера по числу
отказов сохраняется; нет клиентского sort или прогноза будущих заказов.
Проверяются форма ответа, целые безопасные счётчики, уникальные группы и
совпадение пагинации. Дробные pcs и неверные количества отвергаются до кеша.

История заказов открывается на вкладке отказов с INSUFFICIENT_STOCK и тем же
периодом через существующие URL helpers. Она не поддерживает product_id: такой
параметр не отправляется. Admin получает карточку текущего продукта; обе роли —
поиск продукта на складе с UI-выбором UUID. Историческое имя может отличаться
от текущего, а продукт может отсутствовать в остатках; история остаётся доступной.

`currentData` изолирует параметры. Ошибки сети оставляют явно устаревший снимок
только для того же периода; 403 скрывает кешированные строки. Есть загрузка,
пустой отчёт, пустой период, пустая страница, повтор чтения и пагинация.
Mount/focus/reconnect и видимый polling 30 секунд обновляют отчёт. POST orders
инвалидирует IngredientShortages также при неопределённом результате: отказ мог
быть сохранён. POST orders/check не добавляет попытку и не инвалидирует отчёт.

MSW включается только явно в development/test. Он считает distinct attempt_id
из общего хранилища сохранённых отказов INSUFFICIENT_STOCK; повтор ключа читает
тот же результат, успешный заказ и check не увеличивают спрос. Сценарий
shortages-demo добавляет только синтетические исторические группы, большие
агрегаты и страницы. Production использует настоящие запросы.
Проверки с MSW подтверждают frontend; аутентифицированная интеграция S22 и
реальный отказ/повтор на сервере должны фиксироваться отдельным доказательством.
