# История складских движений (F26)

`/stock-movements` и совместимый `/movements` показывают read-only историю для admin, manager и storekeeper. Оператор заказов не монтирует страницу и не отправляет запрос. Ответ 403 скрывает последний список; другие ошибки предлагают повтор и явно отмечают сохранённый список как устаревший.

GET `/stock-movements` использует только опубликованные `product_id`, `batch_id`, `order_id`, `type`, `from`, `to`, `sort=-occurred_at`, `page`, `page_size`. Фильтры находятся в URL; смена фильтра сбрасывает страницу. Даты вводятся в зоне ресторана, нижняя граница включается, верхняя исключается. Неизменённые даты сохраняют исходные дробные секунды. Неверные UUID, тип и период блокируют запрос. После изменения зоны пользователь пересматривает незавершённый период явно.

Схема проверяет четыре типа движения, знак decimal-строки, целые штуки, исторические связи заказа и envelope списка. Количества форматируются через существующий BigInt helper. Название продукта, единица и остаток после операции берутся из исторического ответа: сегодняшние название и баланс их не заменяют. `actor=null` отображается как «Система». Расход заказа обозначается использованием ингредиентов, а не потерей.

Ссылки заказа доступны admin/manager. Общая ссылка склада открывает склад. API движения не содержит supply_id: кнопка «Найти поставку» отдельно ищет точный batch_id в опубликованном GET `/products/{product_id}/batches?status=all`, проходя страницы по необходимости. Затем появляются ссылки поставки и конкретного выбора продукта/поставки на складе. Поиск ограничен 100 страницами по 100 строк; ошибки, отсутствие партии или некорректная пагинация не удаляют исторический список. Запрос партий не меняет показанные исторические количества.

Панель партий склада и детали заказа содержат обратные ссылки с заранее заданными ID. Пустая история, отсутствие совпадений, удалённая страница пагинации, загрузка, ошибка чтения и отказ доступа имеют отдельные состояния. Повторное чтение каждые 10 секунд при активном окне обновляет текущий фильтр. Мутаций истории нет. Форма ручного списания F25 остаётся отдельной историей.

Для демонстрации используйте `VITE_ENABLE_MOCKS=true`: панель содержит сценарии «Движения · …». Все данные синтетические; четыре вида движения включают дробный расход, причину списания и системного автора. Моки не проверяют backend.

Проверки: `bash scripts/frontend-checks.sh`; `cd frontend && npm run test:browser -- stock-movements.pw.ts`. Проверяются четыре ширины 360/390/1024/1440, роли, точные исторические количества, URL, фильтры, страницы, переходы и состояния. Интеграцию с настоящим backend проверяют отдельно с отключённым MSW и выделенной локальной PostgreSQL-базой; DSN и QA-пароли находятся вне репозитория.
