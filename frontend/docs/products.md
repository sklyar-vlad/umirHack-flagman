# Каталог продуктов и категории

`/admin/products` и `/admin/categories` доступны только admin через общую матрицу ролей. Запрещённая роль не монтирует страницы и не отправляет их запросы. Backend остаётся ответственным за окончательную авторизацию каждой операции.

Каталог читает опубликованный `ProductListResponse` из `GET /products`: настройки учёта, а не вычисленные остатки склада. Параметры `search`, `category_id`, `is_active`, `sort=name`, `page`, `page_size` передаются явно; начальная активность `all`, размер страницы 50. Поиск буквальный, порядок и total задаёт сервер. Фильтры хранятся в URL, изменение фильтра сбрасывает страницу. `currentData` не подставляет список от других параметров, transient error помечает последний успешный список как устаревший, 403 скрывает записи. Обновление при возвращении на экран, focus/reconnect и tag invalidation не позволяет навсегда оставить старый каталог после изменений.

Карточка показывает категорию, базовую g/ml/pcs и отображаемую g/kg/ml/l/pcs единицу, стандартный срок в часах, активность и целевой запас. `target_stock=null` означает «Не задан»; строка `0.000` отображается как нулевая цель, положительное значение форматируется точно в единице отображения. Float для количеств не используется. У цели в штуках дробная часть должна быть нулевой. Стандартный срок `null` не заменяется нулём.

Ссылка на склад передаёт название и ID продукта как UI-only выбор, без неподдерживаемого API-фильтра. Создание и редактирование продукта ведут в защищённые `/admin/products/new` и `/admin/products/:id/edit`; прежний `/admin/products/:id` остаётся совместимым адресом редактора. F17 предоставляет полную форму. Возврат сохраняет разрешённые фильтры каталога. Физического удаления нет.

Категории читаются страницами из `GET /product-categories`, с серверным search и sort=name. Выпадающий выбор категорий в каталоге использует существующий полный постраничный read, не обрезает список на первых 100 категориях. Создание использует опубликованный `POST /product-categories` с `{name}`; переименование — `PATCH /product-categories/{id}` с `{name, expected_revision}`. Имена trim, 1–200 Unicode-символов; уникальность и текущую ревизию проверяет сервер. CSRF берётся из действующей сессии общим транспортом.

Редактор переименования предварительно делает свежий GET по ID. Обновление списка, focus и reconnect не заменяют ревизию или грязное имя редактора; только явная загрузка актуальной версии обновляет снимок ревизии. F18 сохраняет предложенное название при таком чтении, показывает актуальное серверное имя и требует отдельного подтверждения ревизии перед повторным PATCH. Неудачное чтение не использует старую запись из cache и сохраняет блокировку отправки. `409 CONFLICT` сохраняет введённое имя; `REVISION_CONFLICT` блокирует сохранение до явного чтения актуальной версии и нового подтверждения пользователем. Ревизия выше допустимого expected_revision блокирует PATCH. Во время записи поля и кнопки отправки/отмены отключены. 422 явно сообщает об отклонённом названии, 404 при PATCH — об отсутствии категории; введённое имя остаётся. При 404 повторная запись заблокирована до свежего чтения/проверки. Отмена грязной формы и уход со страницы требуют подтверждения, Escape возвращает к редактированию. Ошибки 403/404 при чтении редактора не показывают старую запись.

Категорией нельзя управлять через DELETE: такого маршрута в контракте нет. Записи инвалидируют `ProductCategories`, `Products`, `Inventory`, `Dishes`, `StopList`, `HotOffers`, `Procurement`, `Dashboard`; изменения продукта в F17 обновляют соответствующие теги. Запросы записи автоматически не повторяются. После транспортной ошибки/невалидного ответа результат может быть неизвестен: UI просит проверить обновлённый список, поскольку запись могла сохраниться. Backend не публикует идемпотентный ключ для категории; клиент не выдумывает его.

## Проверки и интеграция

MSW включается только явным development/test режимом; production использует реальные requests с cookie/CSRF. Дополнены существующие сценарии продуктов и категорий: пустой/медленный/ошибочный список, медленная запись, конкурирующая ревизия и потеря ответа после сохранения. Синтетическое состояние категорий в sessionStorage сохраняет rename/create при reload и используется каталогом и выбором категорий. Оно не является серверной базой или доказательством транзакции/аудита.

Vitest проверяет URL, контракты, null/zero/positive, фильтры, пагинацию, запрет ролей без GET, CSRF/payload, создание, дубли, конфликт/reload, грязную форму, неизвестный результат и обновление зависимого чтения. Playwright проверяет admin workflow, клавиатуру, loading/error/empty/stale/403, три запрещённые роли и размеры 360/390/1024/1440. Реальная интеграция S07/S17/S15, cookies, CSRF, RBAC, аудит, серверная уникальность и конкурентные ревизии с выключенным MSW остаются непроверенными. Изменение продукта реализовано в F17; проверка реального сервера остаётся отдельной.


## Диалоги и черновик продукта (F18)

Создание и переименование на `/admin/categories` используют общий нативный modal `CategoryDialog`. При открытии фокус переходит на имя; Tab остаётся в диалоге. Escape и кнопка закрытия проходят через защиту несохранённого имени. Отмена подтверждения возвращает в редактор; сохранение/отмена возвращают фокус инициатору, а при исчезновении кнопки из текущего фильтра — кнопке создания. Во время записи закрытие и повторная отправка заблокированы. Вложенное подтверждение обрабатывает Escape самостоятельно.

В F18 `/admin/products/new` предоставлял подготовительный локальный черновик с именем и категорией; F17 заменил его полной формой. Общий диалог создаёт категорию через опубликованный POST, выбирает её ID после обновления справочника и сохраняет уже введённое имя продукта. Отмена/ошибка не меняет прежний выбор. Полная форма F17 использует тот же диалог категории и сохраняет все остальные поля продукта, включая единицы, срок, цель и активность. Черновик F17 восстанавливается после перезагрузки для того же пользователя; подтверждённый уход удаляет его.

`ProductCategories` обновляет все активные подписки существующего полного постраничного read: фильтры каталога/склада/закупок и выбор категории в черновике. Переименование обновляет привязанные названия через прежние теги; dirty-редактор сохраняет собственную ревизию. Дополнительные opt-in MSW сценарии `category-validation-error` и `category-not-found` проверяют отказы записи 422/404 без изменения опубликованных schemas или production transport.


## Создание и изменение продукта (F17)

Форма использует опубликованные `GET /products/{id}`, `POST /products`, `PATCH /products/{id}` и общие cookies/CSRF. Имя обрезается по краям и содержит 1–200 Unicode-символов. Чтение категорий для select также проверяет Unicode-символы, поэтому допустимая категория из 200 emoji остаётся выбираемой. Базовые единицы: g, ml, pcs; отображаемые пары: g/g или g/kg, ml/ml или ml/l, pcs/pcs. Смена базовой единицы явно выбирает такую же отображаемую единицу и не преобразует введённую цель; запрет `UNIT_LOCKED` объясняется ответом сервера.

Цель вводится **в базовой единице**, независимо от отображаемой. Точная конвертация через BigInt принимает точку/запятую и максимум numeric(14,3), без float; штуки целые. Пусто означает `null`, ноль — строку `0.000`. Стандартный срок пустой либо целое 1–2147483647 часов. Активность задаётся явно. PATCH отправляет только изменившиеся нормализованные поля и `expected_revision`: неизменённое поле отсутствует, очистка срока/цели передаёт `null`. Старые партии не получают PATCH и не меняют даты/количества от изменения стандартного срока.

Редактор делает свежий ID-read при открытии; list invalidation/focus/reconnect не подменяют его ревизию. 409 `REVISION_CONFLICT`, `CONFLICT`, `UNIT_LOCKED`, `PRODUCT_IN_USE` (со списком блюд), поля 422 и 404 сохраняют весь ввод. 403/404 начального чтения не показывают старые cached records. Перечитывание предлагается явно, сохраняет предложение, показывает **все** актуальные поля/ревизию и требует подтверждения; можно также явно принять все актуальные значения. Неудачное перечитывание не разблокирует конфликт. У предельной ревизии 2147483647 повторное изменение запрещено.

Неизвестный результат записи (сеть/таймаут/5xx/невалидный ответ) блокирует повторную отправку. Перед запросом сохраняется флаг неопределённого результата. Для PATCH нужно перечитать и проверить текущий продукт; для POST — проверить каталог в новой вкладке и явно разрешить новую попытку. Нет автоматического replay и выдуманного idempotency key. Успех принимается только при валидном Product, совпадающих переданных полях/ID и ожидаемой следующей ревизии PATCH; после успеха черновик удаляется и отображается подтверждение с возвратом к разрешённым фильтрам каталога.

Allowlist черновика содержит только resource ID, строковые поля формы, сравниваемый снимок/ревизию и флаги review/uncertain. Он хранится в Redux и tab-local `sessionStorage` (`flagman.products.v1`), принадлежит пользователю, переживает expiration/reload для того же владельца и удаляется при явном logout/смене пользователя/подтверждённом уходе/успехе. Невалидный незавершённый ввод допустим в черновике; credentials, CSRF и API cache в него не входят. При недоступном browser storage остаётся черновик в памяти. Пока запись ожидается, поля и повторная отправка заблокированы; подтверждение ухода не позволяет бросить запрос.

Мутации обновляют `Products`, `Inventory`, `Dishes`, `StopList`, `HotOffers`, `Procurement`, `Dashboard`; ревизия открытого редактора остаётся локальным снимком. MSW расширяет существующий каталог синтетическими product mutations и сценариями отказов/конфликта/медленной записи/потери ответа. Inventory, выбор продуктов для поставки и procurement используют изменённые настройки; существующие supply/batch snapshots не переписываются. Эти проверки доказывают поведение frontend, но не реальное S17, серверные транзакции, гонки ревизий или аудит.
